# CPU 修复记录与复现边界

审查起点：`34ee6bd4c6bf8a24b5d4b369c3171c2b9b872e7f`。

## 原代码无法直接运行的原因

| 文件/位置（原版本） | 问题 | 修复 |
|---|---|---|
| `pre_process.py` 主入口 | `Solver` 未定义，`epoch_resnet.pth` 没有提供 | 新增明确的 torchvision VGG19 编码器和本地权重接口 |
| `pre_process.py` → `Model.py` | 缓存没有保存模型所读取的 `cnnfeatureList` | 显式保存四层 CNN 特征，与图节点特征分开 |
| 特征接口 | 原预处理拼接同一组四层特征；融合层要求 512+512+256+128=1408，而图入口要求 1536 | 依据文稿区分 F4/F5/F6 图特征与 F5/F4/F3/F2 融合特征 |
| `Main.py` / `Model.py` | 自动选择 CPU 后仍调用 `.cuda()` / `.cuda(0)` | 统一 device，反投影直接张量索引，不重新构造张量 |
| `pre_process.py` / `Model.py` | 预处理 448×448，CNN 融合固定 256×256 | 默认 256，按缓存空间尺寸动态对齐 |
| `Model.py` 反投影 | 不正确处理不同图的节点偏移，存在脱离梯度的张量重建 | 按 PyG `ptr` 切分每张图，局部标签索引保留梯度 |
| 原三个尺度分支 | 预处理 100/300/500，实际 forward 只使用两个尺度，第三分支参数闲置 | 默认文稿 50/100，ModuleList 只建立实际使用的分支 |
| 数据与路径 | 清单、缓存目录硬编码且彼此不一致；跳过前 15 张图 | 命令行清单/路径，从第一张图处理，缓存版本和元数据检查 |
| 损失 | `pytorch_ssim` / `pytorch_iou` 无依赖说明，输出 squeeze 为 BHW | 内置 BCE+SSIM+soft-IoU，五个输出均保留 B1HW |
| 训练/输出 | 无目录创建、可用推理入口、断点恢复或验证选模 | 完整 CLI、latest/best 检查点、续训、独立验证、原尺寸 PNG 导出 |

原来的数据加载器与双层列表 pickle 结构本身配套，不把它误判为单独错误。新缓存改用 `torch.load(weights_only=True)` 可读取的张量和基础类型，避免继续依赖嵌套的 PyG 对象 pickle。

## 依据与尚未恢复的部分

根据作者提供的文稿，第 2 节和图 1/2 描述 VGG19、F4/F5/F6 图节点特征以及另一组四层 CNN 特征；第 3.2 节给出 256×256、K=32、50/100、20 轮和 batch size 4。此次默认值与这些设置对齐，学习率 0.005 沿用原 `Main.py`。

以下内容属于明确的实现选择，不能据此声称已恢复原论文模型：

1. **缺失的编码器。** 文稿写到先在 EORSSD 训练集微调 VGG19，但仓库没有该训练流程/权重；原脚本的 `Solver` 和 `epoch_resnet.pth` 也没有实现。本版本默认使用 torchvision ImageNet VGG19，新增冻结特征提取接口。F6 用 pool5，具有图示 8×8×512（输入 256 时）的形状，但原 F6 的内部算子仍无法确认。
2. **编码器输入。** 使用 torchvision 对应的 RGB/ImageNet mean/std。原残留代码是另一种 BGR/像素均值接口，不能套用到新编码器。
3. **空间处理。** 本版将图像双线性 resize 到方形，掩码最近邻 resize、二值化。文稿称“裁剪”，未提供可恢复的裁剪/增强配方；两者不能认为等价。
4. **跨级连接（已更正）。** 原 forward 反复将首级融合特征送入后续各级；首版 CPU 修复沿用了这一行为。重新放大图 2 并核对式（6）附近的正文后，确认论文要求将“前一层级”融合特征送入下一层，图示箭头也逐级连接。当前已改为 fused_maps[-1]，后两级拼接通道相应调整；新增干预测试检验真实连接来源。format_version=1 解码器检查点被明确拒绝，需重新训练。此前将图 2 描述为首级跨级连接的判断有误。
5. **保留的操作。** GatedEdgeConv、GraphSizeNorm、四级宽度、分支相加和五头监督保留。节点特征在区域均值前的 sigmoid 与原预处理一致。图稀疏化保留原两遍 KNN 操作，不替换成另一个图算法。SNIC 返回的实际区域数可能与目标数不同。
6. **损失实现。** SSIM 使用 sigma=1.5、11×11 高斯窗、零填充、C1=0.01²、C2=0.03²；IoU 使用 1e-6 平滑。小图的窗口缩至可容纳的奇数。原依赖版本未锁定，不能保证和原私有运行环境逐数值一致。
7. **权重兼容性。** 模块名、缓存 schema 已统一，原版 decoder 权重不能直接加载。未提供旧 checkpoint 的可验证映射，不静默丢弃不匹配参数。新编码器 checkpoint 加载也使用 strict=True。

## 后续找到的 EGNet 候选编码器

依据原脚本的文件名、Solver 构造形式和 BGR 均值，找到并下载了 EGNet 官方的 epoch_vgg.pth / epoch_resnet.pth。已新增可选 EGNet VGG16+Conv6 和 ResNet50+ConvertLayer 编码器，并与官方实现逐元素核对；详细来源与结果见 [EGNet 核验记录](EGNET_CHECK.md)。它解决了“找到一套可用显著性预训练编码器”的问题，但并未确认原文实验的 VGG19/EORSSD 微调身份。默认 VGG19 分支不被静默替换。

## 验证方式

```bash
python -m pytest -q
python smoke_test.py --work-dir runs/smoke64 --size 64
python smoke_test.py --work-dir runs/smoke256 --size 256
```

测试覆盖不同图节点数下的反投影值与梯度、区域池化梯度、batch 1/2 所有训练参数参与反传及权重更新、空/满掩码损失、真实 VGG19 层形状、编码器检查点往返、错误权重摘要拒绝、原图稀疏化规则。

完整自检使用实际的 SNIC、VGG19、PyG GatedEdgeConv 和五头损失；数据为合成几何图，编码器随机初始化且固定 seed=0。训练/验证图像独立，恢复训练后导出一张原尺寸 86×66 灰度 PNG。这验证代码闭环，不验证遥感数据精度。

实测结果见 [CPU 验证记录](CPU_VALIDATION.md)。图构造仍沿用原代码的两遍 KNN，和正文“每个节点连接最近 K 个节点”的字面定义不完全相同，尚不能宣称每个方法细节均对应。另有引言写第 3/4/5 层、方法和图 1 写第 4/5/6 层的文字不一致，当前遵循方法节和图 1。

CPU 验证不代表已经验证 CUDA 路径，也不代表已经完成全量 EORSSD 训练或评审要求的补充实验。
